# 通过 Agent 教学发布格式

发布格式教学用于普通剧集的**文件名字段抽取**：作品已知，但陌生发布方式让标题、原始集号或修订版混在一起时，由 Agent 根据真实样本推导格式，再经过预览和人工确认保存。

**手动教学入口、表单与独立批量预览页面已移除。** 后端教学接口、Agent 工具及已保存规则保留；移除页面不会删除或停用历史规则。

它不是第二套识别引擎，也不执行整理、改名、下载或 TMDB 绑定。模板字段通过，不代表 TMDB 身份或最终归档结果已经验证；后续仍使用原来的身份核验、人工锁、预处理、剧集映射与写入确认流程。

## 1. 直接在 Agent 对话中提出需求

使用前需要启用 Agent 并配置可用模型，可从 Agent 输入框旁的设置按钮进入。你不需要填写模板或打开专门的教学页面。

把至少两个真实文件名贴给 Agent，说明正确标题、原始集号、本次开始整理的文件夹，以及文件实际所在目录。例如：

> 本次从 Teaching 文件夹开始整理，这两个文件就放在 Teaching 中，没有子目录。标题都是“星海航行”，分别是第 13、14 集，r2 是修订版，不是第 2 集。请帮我学会这个格式，先预览，再让我确认保存。
>
> `[Example-Team][星海航行][track013r2][1080p].mkv`
>
> `[Example-Team][星海航行][track014r2][1080p].mkv`

以上是合成示例，请替换为你的真实文件名。信息不足时，Agent 应先追问，而不是编造样本、剧名或集号。

## 2. 先核对，再确认保存

1. **推导格式**：Agent 根据样本识别标题、集号和修订版的位置。
2. **真实预览**：后端使用统一解析链，检查修改前后的标题、季集、未匹配与冲突。只要求“预览，不要保存”时，不应创建保存计划。
3. **人工确认**：核对系统确认卡后点击确认，才会保存规则。Agent 的文字回答或“已预览”不代表已经保存。
4. **后续复用**：同范围、同格式的新识别使用保存的规则，不会立即重跑历史任务、改名或移动文件。

每次需要 2–8 个标注样本，至少包含两个不同文件名和两个不同原始集号；批量核对最多 100 个文件名。模板含季号时，样本还需提供原始季号。

- 标题应是文件名中需要抽出的原始片段，不是另一语言的译名或 TMDB 展示名。
- 不要把 `r2`、`v2` 等修订号标成集号。
- 不要把发布第 13 集标成换算后的 TMDB 第二季第 1 集；编号转换仍交给既有剧集映射。
- 样本不一致、特殊篇或冲突可能阻止保存；请核对原因，不要仅凭“命中”判断可归档。

文件名与对话会交给你配置的 Agent 模型处理；教学工具本身不会上传或读取视频内容。规则校验与保存仍在本机完成。

## 3. 告诉 Agent 应在哪些文件中使用

默认先限制在当前目录，避免影响其它作品。说明实际整理起点和文件所在目录即可，不必自己理解或填写 `parent_path` 字段。

目录规则按识别链使用的父目录上下文精确匹配，**不包含子目录**。例如，从 `Teaching` 开始整理：

- 文件直接位于起点：上下文为 `Teaching`。
- 文件位于子目录 `Season 02`：上下文为 `Teaching/Season 02`。

不要将来源 ID、云盘目录 ID 或本地来源的显示别名当成目录上下文；单文件检查和从不同起点发起的扫描也可能使用不同上下文。请让 Agent 根据实际使用的整理入口核对，而不是仅凭绝对磁盘路径猜测。

确需跨作品复用时，需要有意义的固定发布前缀，以及至少两部不同作品的真实样本。这里只复用字段结构，不复用 TMDB ID、季集偏移或集号映射；同一作品的中外文别名不能当成两个不同作品的证据。

## 4. 已有规则与维护边界

- 已保存规则继续用于后续识别，数据库和备份不受前端移除影响。
- Agent 仍保留预览与确认保存能力；管理页面已移除，不应再引导用户寻找“高级手动”或规则列表。
- 后端认证接口仍保留：`/api/tools/release-formats` 用于查询和保存，`/preview` 用于预览，`/{rule_id}` 用于启停与删除。维护操作仍受现有认证、预览凭据及冲突校验约束。
- 修改内容、范围、样本或预览文件名后需要重新预览。重复保存不会建立副本，也不会通过迟到请求复活已删除规则。
- 数据库仍使用原有备份与事务迁移机制；本次仅移除前端，不进行数据迁移或清理。

教学不自动发现作品身份，也不承诺适配全部发布组。请将“字段抽取正确”“TMDB 匹配正确”和“可以执行整理”分开核对。
