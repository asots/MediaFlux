# 显式首次安装

新初始化先支持 **Linux、本地存储及实际成功的目录 fsync / no-replace / SQLite 锁**。原生 Windows 新安装暂缓，已有被认可的 Windows 安装仍走原有正常启动。网络盘、FUSE 或不支持严格同步的卷会被拒绝；不能把 Linux 容器标签当作宿主挂载耐久性的保证。

## 浏览器流程

1. 停止普通服务，检查是否存在需要恢复的旧数据。不要删除 DB、user.env 或恢复文件来绕过检查。
2. 使用与后续 start 完全相同的 UID、卷、路径选择环境。运行以下**一次性**命令（示例路径需替换为真实绝对路径，授权码文件必须尚不存在，数据库、配置及授权码路径的全部祖先目录均不得允许组或其他用户写入；`/tmp` 的 sticky bit 也不例外）：

```sh
umask 077  # 新创建的目录和敏感配置只允许当前用户访问
python mediaflux.py initialize --data-dir /owned/mediaflux \
  --confirm-new-installation --expect-env-sha256 absent \
  --web --grant-file /owned/mediaflux/setup-code \
  --host 127.0.0.1 --port 1258 --setup-origin http://127.0.0.1:1258
```

3. 操作者在本机私下读取 setup-code 文件，不把它发到聊天、URL、环境变量或日志。浏览器打开该 origin 的 `/setup`，填写一次性码及管理员用户名、密码和确认密码。码最长有效 15 分钟，仅限生成它的存活进程；遗留文件不能重新授权。
4. 页面显示成功后，初始化进程退出。运行相同路径配置的 `python mediaflux.py start --data-dir /owned/mediaflux`，重新 `/login`。不自动登录、不热切换业务服务。

容器示例：先 `docker compose stop mediaflux`，再用同服务配置执行 `docker compose run --rm --no-deps --service-ports mediaflux python mediaflux.py initialize --data-dir /app/db --confirm-new-installation --expect-env-sha256 absent --web --grant-file /app/db/setup-code --host 0.0.0.0 --setup-origin https://你的可信入口`；成功退出后才 `docker compose up -d`。默认 host 网络下 service-ports 无实际影响。保持镜像既有 PUID/PGID 和卷权限。远程浏览器必须经可信 HTTPS 代理或认证隧道；Origin/Host 校验不加密明文 LAN。

`--data-dir` 不覆盖已配置的 `MEDIAFLUX_CONFIG_DIR`。Docker 默认 data/config 均为 `/app/db`（平铺 DB/user.env）；源码路径可能为 data/db/mediaflux.db 与独立 config/user.env。已有 user.env 时，将 `absent` 换为该文件当前精确字节的 SHA256；无关配置保留，字节或 inode 变化会拒绝。

## 预配置部署 / CI

仅选取明确需要的 string 键值，以私有 JSON 文件通过 FD0 输入；最多 64 KiB，严格 UTF-8、无重复键，管道有有限读取期限。禁止将整个 ambient environ 导出。字段可包含 `MEDIAFLUX_INITIALIZED=1`、`ENV_WEB_PASSPORT`、`ENV_WEB_PASSWORD`、`WEB_SECRET_KEY` 和业务配置；路径选择键不得放入 JSON。未给 secret 时在授权事务中生成并持久化，不预先发布 fallback 文件。

```sh
umask 077  # 新创建的目录和敏感配置只允许当前用户访问
python mediaflux.py initialize --data-dir /owned/mediaflux \
  --confirm-new-installation --expect-env-sha256 absent --settings-fd 0 < /private/selected-settings.json
```

Docker 使用同卷、UID 与镜像，`-i` / `-T` 无 TTY 传 FD0。不要把密码/授权码放在 argv；不要用 `initialize || start`、自动重试循环或入口脚本自动初始化。只在退出码 0 后启动普通服务，普通 start 从物理 env+DB 读取，不依赖 ambient 管理员凭据。与 ambient 管理员/secret 冲突时仅报告键名并拒绝。

## 失败与恢复

新操作拒绝任何现存 DB、SQLite sidecar/journal、待恢复 env 和 restore journal。成功的 stable 回执必须在真实文件同步、目录同步和最终 COMMIT 返回之后。发布后的失败保留 changing/unknown 证据，不删除、不回滚假定、不重放、不提升孤立 stage。COMMIT 异常即使冷读观察到 stable 也返回非成功。请停服检查备份与存储，不通过重新 initialize 试探修复。

普通未安装 `/setup` 只显示指引，POST 不授权，`/readyz` 与 `/healthz` 返回 503；启动器仍可创建运行目录、锁和 PID（这不等于写入业务 DB/env/secret）。已有认可的 legacy DB 使用正常迁移与真实迁移前 ZIP，不走新初始化。
